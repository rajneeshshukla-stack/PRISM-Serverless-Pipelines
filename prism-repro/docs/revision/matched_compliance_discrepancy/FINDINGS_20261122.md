## 2. Cause: a controlled matched replay

**Driver.** `matched_replay.py` reruns exactly the stored jobs on the test weeks: PRISM at the six eps values and
QuantProv-q90 at the ten a values, in four scenarios on each of the five development traces. One code tree and one
configuration change are used per set. Commands are in `replay_20261122/jobs.txt` and timing in `run.log`
(13:15-13:43 UTC, 22 Nov 2026, 4 parallel jobs). The 1,344 rows and the analysis files are hashed in
`replay_20261122/SHA256SUMS`.

**Control.** The current tree with its defaults reproduces the grid_studies row bit for bit (trace 101, PRISM 0.005,
stationary).

| Set (this laptop unless stated) | 1.0% estimate | Change from the previous set |
|---|---|---|
| stored rows (Linux) | -0.36 +/- 3.30 | |
| v1-submitted tree (3b4bc33), defaults | -0.68 +/- 1.47 | -0.32 +/- 2.14 (per trace -3.2, -0.2, +1.4, -0.0, +0.4) |
| HEAD with both switches reverted (occupancy, sampled attainment) | -0.68 +/- 1.47 | 0.00; QuantProv rows 200/200 and PRISM rows 114/120 identical; the other 6 differ in cost by at most 0.0004% (`extra_checks.txt`) |
| HEAD, exact attainment, occupancy | -2.39 +/- 1.91 | -1.71 +/- 1.82 |
| HEAD defaults, adding Erlang-B | -2.27 +/- 2.02 | +0.12 +/- 0.47 |

**Opposite order.** Switching Erlang-B on first gives +0.97 +/- 1.05 (to +0.29 +/- 1.60). Adding exact attainment
after that gives -2.55 +/- 1.30.

**What each switch does at a fixed setting:**
- **Exact attainment** leaves cost unchanged for both families. It lowers violating windows by 0.32 points (PRISM) and
  0.37 points (QuantProv-q90) on average, by different amounts per setting (range -3.42 to +0.60 points). That moves
  where each frontier crosses 1.0%; on trace 102 it accounts for -4.0 of the -4.2-point shift.
- **Erlang-B** changes only PRISM: cost -2.32% (range -3.89 to -1.45%) with violating windows +0.19 points. Under
  exact attainment its frontier barely moves.

**Attribution.**
- **Supported by the controlled comparison.** On this laptop, the change from the submitted code (-0.68) to the
  current code (-2.27) is reproduced by switching exact attainment (1ab053c) and the Erlang-B risk model (f119bee)
  alone. Exact attainment carries most of it in either order. Every other code change since v1-submitted, tested
  jointly, leaves these rows unchanged.
- **Not isolated.** The remaining -0.32 points of the stored-to-current shift lie between the stored Linux rows and
  the same submitted tree on this laptop. No stored row is reproduced here, including traces 104-105, whose stored
  source is reported AST-identical to the tag (mean absolute cost change 1.65% and 1.06%). The library versions are
  the same; the OS, the Python patch release (3.12.3 against 3.12.9) and the CPU differ, and none was varied
  separately. For traces 101-103 the stored source af08337 is also unavailable. No cause is attributed for this part.
- **Earlier reading corrected.** The previous README noted that PRISM costs about 2% less on the current code. That is
  the Erlang-B switch, and it is not what moves the 1.0% estimate.

## 3. Interpretation

- **The two estimates are not statistically distinguishable.** The paired change is -1.91 +/- 2.42 points.
- **The conclusion is not stable across revisions.** With the corrected, exact attainment the interval excludes zero
  narrowly (-2.4 +/- 1.9 and -2.3 +/- 2.0). With the submitted 100-request sample it includes zero (-0.7 +/- 1.5 on
  this laptop, -0.4 +/- 3.3 on the stored rows).
- **Which estimate is better founded.** The exact-attainment figure rests on the corrected metric (R5.M1), so it is
  the better-founded of the two in the fast simulator. Its margin from zero is small, however: five traces, post hoc,
  pre-calibration, with no event-level or closed-loop check.
- **What this supports.** Neither set supports an established cost difference between PRISM and QuantProv-q90 at
  matched compliance. At 1.5% and 2.0% the current-code intervals include zero (`../grid_studies/summary_posthoc.txt`).
  The case fits R7.6 exactly: a small numerical difference that should not be read as superiority.
- **R5.M7(d), as worded, still holds on the revised code** for the tables it names:
  - Table VI analogue at f77c00c, which contains both switches, on this laptop (`../table6_versions/comparison.txt`,
    scikit-learn 1.8.0): PRISM minus QuantProv-q90 per scenario is +1.6 +/- 2.3, +1.3 +/- 2.2, +0.0 +/- 3.5 and
    -0.1 +/- 3.1%. Later source changes were not checked for identity on these rows.
  - Table XII analogue at HEAD (`replay_20261122/extra_checks.txt`): +1.6 +/- 4.0%.

  Every one of these intervals includes zero. The tracker line of 22 Nov saying that (d) "holds for the stored rows
  only" overstated the issue.

**Left open.**
- Which figure the paper reports: that is settled by the regeneration on one implementation, with the closed-loop
  event-level evaluator and measured constants (R2.1, R2.15, R3.6).
- The cause of the platform-level difference.
- An equivalence statement, which would need a margin fixed in advance (the author's choice).

## Line endings (22 Nov 2026)

Applies to `replay_20261122/SHA256SUMS`, with companion `replay_20261122/SHA256SUMS.lf`. `SHA256SUMS.pre_redaction` hashes the earlier CRLF working copies.

Python on Windows wrote the JSON row files with CRLF line endings, and Git (core.autocrlf=true) stores them with LF. The checksum lists named here hash the CRLF working copies. Their `.lf` companions hash the stored LF content; use those on an LF checkout. The companions were written 22 Nov 2026 from the committed blobs, after checking that each blob is the LF form of the listed file.
