# Data card

## 1. Evaluation workloads — SYNTHETIC (generated, not bundled)

| Field | Value |
|---|---|
| Provenance | Generated by `prism_repro.workload.generate_trace(seed, scenario)`; structure from manuscript §5.2, unstated parameters fixed a priori (ASSUMPTIONS D14) |
| Seeds | Evaluation 101–105; development 7 (smoke tests and demo only) |
| Size | 28 days × 1,440 minutes = 40,320 per-minute counts per trace and scenario; ≈600 executions/min on average (≈24 M executions per trace) |
| Schema | `counts[int64 ≥ 0]` per minute; `rate`, `baseline` (float, executions/min); `dow` (0 = Monday); `meta` (seed, scenario, params, `synthetic: true`) |
| Splits | train days 0–13, validation 14–20, test 21–27 (minute ranges in `workload.split_bounds`) |
| Scenarios | stationary, growth, bursty, new_spike (main); shifted_triggers (feature ablation only) |
| Leakage controls | forecaster targets end before day 14; selection on validation only; history baselines see only minutes before the evaluated week; conformal offsets use outcomes after a two-epoch delay; test `test_no_lookahead` |
| Checksums | SHA-256 of each trace's counts recorded in every result row (`data_sha256`) |
| Licence / redistribution | Generated data; no third-party content. Not bundled because it regenerates deterministically in seconds |
| Quality checks | tests: identical first 21 days across scenarios, mean rate within 8 % of 600, growth +40 % after ramp, new-spike multiplier, determinism |
| Intended use | Comparing provisioning policies *within this simulator* |
| Limitations | Not real traffic. Generator parameters are assumptions; conclusions about real platforms cannot be drawn from it |

## 2. Simulator random draws (common random numbers)

Per (trace seed, week): peak-concurrency quantile levels, intensity factors, and per-minute samples of 100 requests × 4 stages (execution, orchestration, initialisation multipliers, cold-start uniforms) — `simulator.WeekDraws`. Event-level: per request and stage draws — `des.EventDraws`. All seeded with `numpy.random.default_rng([seed, key])`; identical for every policy.

## 3. Demonstration fixture (bundled)

`data/fixtures/example_trace_SYNTHETIC_seed7_day1.csv` (+ `.meta.json` with SHA-256): first day of the development trace; columns `minute,count`. For the CSV loader and schema only — **not** research evaluation data.

## 4. External / real data — Huawei Private 2023 (experiment R1, post hoc, added 31 Oct 2026)

`data/real/huawei_fn{150,72,60,183,42}.csv` (columns `minute,count`; 40,320 minutes each) are derived from the public **Huawei Private 2023** serverless trace, *requests per minute* (A. Joosen et al., "How does it function? Characterizing long-term trends in production serverless workloads," ACM SoCC 2023; https://github.com/sir-lab/data-release; licence **CC BY 4.0**). Derivation (`data/real/make_csvs.py`, `data/real/pick.py`): days 28–55 of the release (28 consecutive days), functions 150, 72, 60, 183, 42 (missing minutes = 0 requests; none missing in these functions), each thinned binomially to a mean of 600 executions/min with seed 20261031 + function id. `data/real/traces_meta.json` gives source means, thinning probabilities, week means and SHA-256 of each derived series. The data are anonymized request counts; no personal data. Changes from the original: subset of functions and days, binomial thinning. Experiment R1 (`experiments/run_real_traces.py`, analysis `scripts/revision/analyze_real_traces.py`) replays them through the unchanged protocol; arrivals are real, service/initialization/latency remain simulated. The Azure Functions 2019 trace was not used (14 days, shorter than the 28-day protocol).

## 5. Results data

`results/raw/<EXP>/rows.jsonl`: one JSON row per simulated run (configuration, seeds, data and source checksums, timestamps, runtime, all metrics). `results/raw/<EXP>/arrays_seed*.npz`: per-run window attainment, late records, record counts, per-epoch provisioning and memory schedules, PRISM feasibility/excess/κ per epoch — sufficient to recompute window-level metrics, the infeasibility table and the event-level replays.
